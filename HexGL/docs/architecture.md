# Architecture de HexGL — état actuel

Document descriptif, établi par lecture du code et par exécution du jeu en navigateur headless. Il ne décrit que l'existant : aucune correction ni piste d'évolution n'y figure.

## 1. Stack et points d'entrée

**Stack**
- Application web statique : HTML + CSS + JavaScript, sans `package.json`, sans étape de build ni gestionnaire de dépendances.
- Rendu 3D : **Three.js** ancien, copie embarquée (`libs/Three.dev.js`, révision `50dev` ; `libs/Three.r53.js` n'est utilisée que par `bkcore.coffee/tests.html`) + post-traitement (`libs/postprocessing/*`, `libs/ShaderExtras.js`).
- Autres bibliothèques embarquées : `Detector.js`, `Stats.js`, `DAT.GUI.min.js`, `leap-0.4.1.min.js` (Leap Motion).
- Code applicatif : namespace global `bkcore` (pas de modules ES/CommonJS). Une partie est écrite en **CoffeeScript** (`bkcore.coffee/*.coffee`, `launch.coffee`) et livrée compilée (`*.js` versionnés à côté des sources, en-têtes « Generated by CoffeeScript 1.4.0 / 1.7.1 »). Le reste de `bkcore/` est du JavaScript écrit à la main.
- Audio : Web Audio API (`bkcore/Audio.js`) avec repli sur `Audio` HTML ; fichiers `.ogg` dans `audio/`.
- Analytics : Google Analytics historique (`ga.js`, compte `UA-26274524-4`) injecté depuis `index.html`.
- Licence indiquée dans les en-têtes : CC BY-NC 3.0 ; le `README.md` annonce la licence MIT.

**Points d'entrée**
| Fichier | Rôle |
|---|---|
| `index.html` | Page unique du jeu ; charge tous les scripts dans l'ordre (libs → `bkcore.coffee/*` → `bkcore/threejs/*` → `bkcore/Audio.js` → `bkcore/hexgl/*` → `tracks/Cityscape.js` → `HexGL.js` → `launch.js`). |
| `launch.js` (compilé depuis `launch.coffee`) | Menu, options (paramètres d'URL), détection WebGL, enchaînement des écrans, appel de `init()`. |
| `formation/tests/index.html` | Page des tests QUnit. |
| `manifest.webapp`, `package.webapp`, `cache.appcache` | Packaging Firefox OS / cache hors ligne (voir §4). |

## 2. Flux principal de lancement

1. `index.html` charge les scripts ; `bkcore.Audio.init()` s'exécute dès le chargement de `Audio.js`.
2. `launch.js` lit les paramètres d'URL via `bkcore.Utils.getURLParameter` : `controlType`, `quality`, `hud`, `godmode` (valeurs par défaut : clavier ou tactile selon `isTouchDevice()`, qualité 3, HUD 1, godmode 0). Chaque ligne du menu (`#s-controlType`, `#s-quality`, `#s-hud`, `#s-godmode`) cycle sur ses valeurs au clic. L'écran d'accueil `#step-1` contient aussi un bloc statique `#acme-brand` (logo `formation/identite/logo.png`, nom « ACME », message d'accueil), mis en forme par `css/acme.css` ; `#title` (logo HexGL) y est masqué. Aucun script n'intervient sur ce bloc. `#s-godmode` est masqué (`display:none`) dans `index.html`.
3. Si `canvas.getContext("webgl")` échoue, `#start` affiche « WebGL is not supported! » et pointe vers `http://get.webgl.org/`. Sinon, clic sur `#start` → affiche `#step-2` (image d'aide `css/help-N.png`).
4. Clic sur `#step-2` → `#step-3` (barre de progression) → `init(controlType, quality, hud, godmode)` crée `bkcore.hexgl.HexGL` (exposé en `window.hexGL`) et appelle `hexGL.load(...)`.
5. `HexGL.load` → `track.load(opts, quality)` (`tracks/Cityscape.js`) : un `bkcore.threejs.Loader` charge textures, géométries, « analysers » (images de collision/hauteur lues pixel par pixel) et sons, avec un jeu de ressources selon `quality` (< 2 : textures LOW ; sinon version complète).
6. `onLoad` → `hexGL.init()` (`initHUD`, `track.buildMaterials`, `track.buildScenes`, `initGameComposer`) → `#step-4` affiché → `hexGL.start()`.
7. `start()` : `RenderManager.setCurrent("game")`, boucle `requestAnimationFrame` (`update()` → `gameplay.update()` + `manager.renderCurrent()`), puis `initGameplay()` crée `Gameplay`, le démarre et lance les sons `bg` et `wind`.
8. `Gameplay.update` déroule le décompte (étapes 0→4 : « Get ready », 3, 2, 1, « Go »), active `shipControls`, puis appelle le mode (`timeattack`). 3 tours (`maxLaps = 3`) ; fin sur FINISH ou DESTROYED.
9. `onFinish` → `shipControls.terminate()` + `displayScore()` → affiche `#step-5` (temps final) ; un clic sur `#step-5` recharge la page. `Échap` appelle `HexGL.reset()` (redémarrage de la course).

## 3. Modules, fichiers et assets

**Coeur du jeu — `bkcore/hexgl/`**
- `HexGL.js` (446 l.) : orchestrateur (options, renderer, composer d'effets, HUD, gameplay, écran de score).
- `Gameplay.js` (230 l.) : machine à états de la course, tours, checkpoints (lus par la couleur d'un pixel de l'image de collision), modes `timeattack` / `replay` (le mode `survival` est déclaré mais vaut `null`).
- `ShipControls.js` (806 l.) : physique et contrôles du vaisseau (clavier, tactile, orientation, gamepad, Leap Motion), collisions, hauteur, boost, bouclier.
- `ShipEffects.js`, `CameraChase.js`, `HUD.js`, `RaceData.js` (enregistrement/rejeu), `Ladder.js` (classement distant).
- `tracks/Cityscape.js` (521 l.) : seule piste ; liste des ressources, construction des matériaux/scènes, positions de départ, points de passage (`checkpoints`: 0, 1, 2), `pixelRatio = 2048/6000`.

**Moteur — `bkcore/threejs/`** : `Loader.js` (chargement groupé avec progression), `Preloader.js`, `RenderManager.js`, `Particles.js`, `Shaders.js` (949 l., shaders GLSL en chaînes).
**Audio — `bkcore/Audio.js`**.

**Utilitaires CoffeeScript compilés — `bkcore.coffee/`** : `Utils` (matériau normal, `projectOnScreen`, `getURLParameter`, `getOffsetTop`, `scrollTo`, `updateClass`, `request`, `isTouchDevice`), `Timer` (`start/pause/update/getElapsedTime`, statiques `msToTime`, `msToTimeString`, `zfill`), `ImageData` (pixels d'une image via canvas : `getPixel`, `getPixelBilinear`, `getPixelF`, `getPixelFBilinear`), `controllers/` (`TouchController`, `OrientationController`, `GamepadController`), `threejs/Particles`.

**Assets**
- `geometries/` : `bonus/`, `booster/`, `ships/feisar/`, `tracks/cityscape/` et `tracks/edge/` (modèles JSON Three.js).
- `textures/` : `bonus`, `hud`, `particles`, `ships/feisar`, `skybox/dawnclouds`, `tracks/cityscape`, `checker.png`. Un dossier `textures.full/` existe en parallèle (le README indique de permuter les deux dossiers pour les textures pleine taille).
- `audio/` : `bg`, `wind`, `boost`, `crash`, `destroyed` (`.ogg`) + `LICENSE`.
- `css/` : `multi.css`, `fonts.css`, `acme.css` (surcharges de l'écran d'accueil pour l'événement ACME, chargé après `multi.css`), `touchcontroller.css`, police Bebas Neue (4 formats), images d'aide et de menu.
- `replays/cityscape-casual/bkcore.replay.json`.
- Hors jeu : `formation/` (`identite/` charte + logo ACME, `tickets/company-event.md`, `tests/`), `package.zip`, icônes `icon_*.png`, `favicon.png`.

## 4. Dépendances et zones legacy à risque

- **Three.js `50dev` figé** et API correspondante (`THREE.JSONLoader`, `physicallyBasedShading`, `shadowMapSoft`, `Vector3` sans `toArray`…). Le code applicatif en dépend étroitement (HexGL.js, Cityscape.js, Shaders.js).
- **Deux copies de Three.js** (`Three.dev.js`, `Three.r53.js`) ; `Editor.html` + `Editor_files/` dans `libs/`.
- **Variable globale `bkcore`** et ordre de chargement des `<script>` : aucun module, dépendances implicites.
- **Sources CoffeeScript + JS compilé versionnés ensemble**, compilateurs de versions différentes (1.4.0 et 1.7.1). `bkcore.coffee/threejs/Particles.js` diffère de `bkcore/threejs/Particles.js` (seule la seconde est chargée par `index.html`).
- **Chargement par XHR / lecture de pixels de canvas** (`Loader`, `ImageData`, `Audio`) : exige un serveur HTTP ; `ImageData` positionne `crossOrigin = "anonymous"`.
- **Services externes codés en dur** : Google Analytics `ga.js` (UA), `http://hexgl.bkcore.com/` (favicon, og:image, partage), Twitter/Facebook sharer en `http://`, `http://get.webgl.org/`.
- **Packaging Firefox OS** : `manifest.webapp` référence `launch_path: /index-mobile.html`, fichier absent du dépôt ; `cache.appcache` (AppCache, API dépréciée) liste des fichiers de l'époque.
- **Leap Motion** (`leap-0.4.1`) : `ShipControls` lève `Error("Unable to reach LeapJS!")` si `Leap` est nul.
- **WebGL** : sans contexte WebGL, le jeu n'est pas jouable (message dans le menu).
- **Performances** : le jeu dépend du GPU ; en rendu logiciel (headless SwiftShader) il fonctionne en qualité LOW (`?quality=0`).

## 5. Fonctions et modules testables automatiquement (QUnit)

**Existant** — `formation/tests/index.html` charge `vendor/qunit-2.26.0.js`, `bkcore.coffee/Utils.js` puis `browser-tests.js`. Il redirige vers `?hexgl_poc=ok` si le paramètre manque. Exécution : manuelle (ouvrir la page) ou via `ci-chrome.bat` / `ci-chrome.sh` (Chrome/Edge headless, `--dump-dom`, codes de sortie 0/1/2 d'après `data-test-status` sur `<html>`). Exécuté via un driver Playwright : 4 tests, 7 assertions, tous verts.

Tests présents (module « HexGL — bkcore.Utils ») : `updateClass` (ajout, suppression), `getOffsetTop` (cumul parent/enfant sur des objets factices), `getURLParameter`. Le statut « pass » exige `count >= 4`.

**Candidats testables sans WebGL ni chargement d'assets**, avec les mêmes outils (script à ajouter dans `index.html` de test) :
- `bkcore.Timer.msToTime`, `msToTimeString`, `zfill` (fonctions statiques pures) ; `Timer.start/pause/update/getElapsedTime` (dépendent de `Date`).
- `bkcore.Utils.isTouchDevice`, `bkcore.Utils.request` (XHR, testable avec un serveur de test), `scrollTo` (DOM).
- `bkcore.ImageData` : `getPixel`, `getPixelBilinear`, `getPixelF`, `getPixelFBilinear` — nécessitent une image chargée (data-URI ou petit PNG) et un canvas 2D ; `getPixel` hors bornes renvoie un pixel nul.
- `bkcore.hexgl.RaceData` (`tick`, `applyInterpolated`, `reset`, `export`, `import`) avec un `shipControls` factice.
- `bkcore.hexgl.Gameplay` (compteur de tours, enchaînement des étapes, `checkPoint`) avec `hud`, `shipControls`, `analyser` factices.
- `bkcore.Audio` (API `play/stop/volume`) : dépend de `AudioContext` du navigateur.

**Difficilement testables en l'état** (couplés à Three.js/WebGL/DOM/chargement) : `HexGL` (constructeur crée un `THREE.WebGLRenderer`), `ShipControls.update/collisionCheck/heightCheck` (cartes de collision et de hauteur), `Cityscape.load/buildScenes`, `HUD`, `Particles`, `Shaders`, `launch.js` (code exécuté à l'import, manipule le DOM de `index.html`).

## 6. Bugs, dettes et anomalies remarquables

Constatés à la lecture du code (non corrigés) :

1. `HexGL.js:228` — `JSON.Stringify(...)` (S majuscule) : `TypeError` si ce chemin s'exécute. Il n'est atteint que lorsque `opts.gameover` est `null` ; `launch.js` le fournit toujours (`#step-5`), le chemin est donc inactif dans `index.html`.
2. `HexGL.js:222-228` — les clés `localStorage` sont construites avec `t = this.track` (un objet) : `score-[object Object]-casual`, `race-[object Object]-replay`. `Gameplay.start` lit `race-<track.name>-replay` : les deux clés ne coïncident pas.
3. `Ladder.js` : `bkcore.hexgl.Ladder.global` est défini mais `load` et `displayLadder` utilisent `bkcore.Ladder.global` (inexistant) ; la requête vise l'URL `"nothing"` ; la condition `!bkcore.Ladder.global[track][mode] == undefined` est toujours fausse. `Ladder.js` n'est pas chargé par `index.html`, alors que `HexGL.displayScore` référence `bkcore.hexgl.Ladder`. Le commentaire « Ladder save — Undisclosed » signale du code retiré.
4. `Gameplay.js:101` — `self.result.REPLAY` au lieu de `self.results.REPLAY` : erreur à la fin d'un rejeu. Le mode `survival` est déclaré à `null` : `this.modes[this.mode].call(this)` échouerait.
5. `Gameplay.modes.timeattack` utilise `this.maxLaps` alors que `this` dépend de l'appel (`.call(this)`) — fonctionne par construction d'appel, fragile.
6. `HexGL.js:20,105` — `this.a = window.location.href` et un test `if(this.a[15] == "o")` commenté (vestige de verrouillage par domaine).
7. `Utils.getURLParameter` met en cache `URLParameters` une fois pour toutes ; les tests doivent le remettre à `null`.
8. `index.html` : deux éléments `id="ctrl-help"` (dans `#step-2` et `#step-5`) ; `#finish*` (utilisé par la branche alternative de `displayScore`) n'existe pas dans la page.
9. `GAMEOVER` : `console.log('GAMEOVER')` laissé dans `ShipControls.js` ; plusieurs `console.log` commentés dans le code.
10. `textures/particles/` contient `cloud - Copie.png` et `spark - Copie.png` (doublons de fichiers).
11. En-têtes de licence incohérents (CC BY-NC dans le code, MIT dans le README).
12. Seule la piste `Cityscape` est référencée ; `geometries/tracks/edge` n'est pas utilisée par `index.html`. `Preloader.js`, `Ladder.js` et plusieurs passes de `libs/postprocessing` (`DotScreenPass`, `FilmPass`, `SavePass`, `TexturePass`) ne sont pas chargés par `index.html`.
13. `.gitignore` ignore `/HexGL/formation/tests/rapport_erreur.html` (chemin relatif à la racine du dépôt parent).
14. Couverture de tests : 4 tests sur `bkcore.Utils` uniquement ; aucun test de `Timer`, `ImageData`, `Gameplay`, `RaceData`, ni de non-régression du lancement.
